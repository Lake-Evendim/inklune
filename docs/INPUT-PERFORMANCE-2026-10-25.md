# 快速输入与连续删除的延迟修复

## 根因

1. 敲击动作串行执行，每次约 148ms，折行还附加进纸时间。旧队列允许五个待执行动作，快打时未落下的字形被隐藏，形成明显的文字积压。每次删除又取消并重新安排动画帧，系统按键重复会反复打断运动。
2. 每次编辑重新拆分全文、生成所有字形元素；单字组件缓存后，React 仍需遍历数千个子组件。长纸页的处理开销随全文长度增加。
3. 字形显隐的 style 变化触发整页测量，纸面又被运动、光照和 DOM 观察器多次调用。字形块重绘逐字读取 computed style，既重复测量也重复上传纹理。
4. 运动 CSS 变量从根节点向全部字形继承，机械帧会牵连正文样式计算。

## 修复

- 单次按键保留完整敲击与接触显字。连续输入及时显示正文，只保留最新待执行机械动作，缩短运动至 64ms，并取消快速输入中的额外折行等待。
- 连续删除更新活动动作的终点，保留已安排的帧；文本修改始终完整执行。
- 复用未改变的字形和墨迹种子，按 64 个字形组成缓存组，降低 React 遍历与临时对象分配。字形差异边界持续扩展至新旧字符簇均完整，覆盖旗帜重新组合等 Unicode 情况。
- 合并纸面绘制请求；字形显隐只标记对应墨迹块。布局变化比较新旧字形位置，只重绘变化区域；折行、字体和尺寸变化仍正确重新测量。收拢的光标不再使全部墨迹块重绘。
- 运动参数注册为不自动继承的 CSS 属性，仅让纸张运输与机械部件显式继承。缓存句点测量和未变化的光照场。

纸墨颗粒、真实字体、物理像素对齐与夜间灯光范围保持原有视觉设计。

## 验证

实际 App 使用临时工作区，不读写本地信盒。开发版本，在同一前台嵌入式浏览器中，对约 2,800 字纸页分别连续插入 40 次、删除 60 次；请求间隔设为 20ms，实际间隔受处理耗时影响。

| 日间长页指标 | 原版 | 修复后 |
| --- | ---: | ---: |
| 输入处理耗时 P95 | 132.7ms | 30.5ms |
| 删除处理耗时 P95 | 154.2ms | 20.9ms |
| 字形取消隐藏的延迟 P95 | 1167.8ms | 15.8ms |
| 输入帧间隔 P95 | 175.5ms | 35.6ms |

字形延迟按动画帧中观察到的显隐状态计时，不包含屏幕呈现延迟；最终 GPU 绘制可能再等待一帧。这些是此测试环境的开发版本结果，不等同于所有设备上的帧率保证。早期后台测试受浏览器帧率限制影响，未用于上述对照。

- 日间/夜间、短页/长页、擦除/划线删除共 10 项性能场景：正文与镜像一致、无遗留隐藏字形、动画最终归位。
- 16 项实际输入动作回归：单次敲击、字锤伸缩、空格、粘贴、滚动与选区、中文输入法草稿/确认、删除、换行与划线残迹。
- 12 项灯光范围回归：780px/320px 纸宽、经典/玄武岩套件及不同灯光参数；灯口下方保持原有环境亮度。
- 47 项单元检查及生产构建通过。

开发服务中可运行 `/tests/input-performance.html` 与 `/tests/interaction.html`。保持页面在前台，避免浏览器后台限速干扰测量。
